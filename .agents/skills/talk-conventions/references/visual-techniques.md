# 見た目の技術

デッキを作って効いた技術のうち、ほかのデッキにも効くもの。色の値やグラフの座標は
デッキごとに違うので、ここには置かない。それはデッキの `theme.css` の冒頭が持つ。

dek の lint の規則そのものは写さない。正本は `bunx dekc help --agent` と、
`talks/AGENTS.md` の dek ブロック。ここに書くのは、その規則の下で踏んだことと、
どう避けたか。

## 色に仕事を持たせる

- 意味を運ぶ色相は2つにする。論の両側に1つずつ持たせ、その間をグラデーションにする。
  グラデーションは1枚に1語と、移る・問い直す矢印にだけ使う。本文に塗ると、どこにも効かなくなる
- 地は章、色相は意味、墨は終点。章扉・命題・締めを墨の地にし、連鎖や工程の最後だけを墨で塗る
- 無いもの・未検証・走らなかったものには色相を使わない。破線の枠、淡い灰の面、弱い字で描く。
  走らなかったものは斜線、否定と古いものは取り消し線にする。
  **破線はこの3つにだけ使う。** 循環の軌道や戻り道まで破線にすると、「無い」と読まれる
- 部品は `--c` / `--c-soft` / `--c-line` だけを読み、`data-tone` が値を入れる。
  語の印と図の要素に同じ属性を付けると、色で結べる
- 型は色ではなく形で分ける。グレースケールでも、色覚の模擬でも分かれるようにする。
  色相の組は、1型・2型の模擬で灰に寄らないものを選ぶ。寄った色は、灰で描いた「無いもの」と混ざる
- 規則は `theme.css` の冒頭で宣言し、作り終えたら `dekc shot --sheet` と
  `rg 'dashed|amber' slides/*.css` で実際と突き合わせる。途中で崩れる。
  古い判断を破線と斜線で描いていて、「無い」「走らなかった」と同じ形になっていた（踏んだ）

### コントラスト

Radix の段で組むと、次の組が 4.5:1 に届かない。どれも `dekc lint --visual` が拾う。

- 段 11 の字を段 3 の面に載せる。blue と tomato で 4.3:1。面を段 2 にするか、字を段 12 にする
- amber の段 11 の字を amber の段 3 の面に載せる。4.2:1。字は sand-12 にする
- 斜線の面に字を載せる。線の色が地として測られ、sand-6 の線で sand-11 の字が 4.3:1 に落ちた。線を sand-5 にする
- 線や glow の上に置いた札。札に地の色の面を敷き、線が字の下を通らないようにする
- 点の格子を打った紙に、色相の段 11 の字をじかに置く。字が点に重なると、点の色が地として測られて 3.8:1 になる。
  重なるかは書体で決まるので、手元では通って CI（Linux の書体）でだけ落ちた（踏んだ）。
  色の字は面に載せるか、地の色の面を敷く

## 図の文法

- 楕円の循環。駅は `--i` から角度を出し、`--rx` / `--ry` の楕円の上に置く。
  2つの循環を重ねるときは、内側の楕円を別の変数で持つ
- 同じ座標の図を何度も出す。座標は `theme.css` に1か所だけ置き、枚ごとに変えるのは
  `data-lit` などの属性だけにする。見え方（どの範囲を見るか）は新しい図にせず、同じ図の照らし方で描く。
  照らさないノードは灰に落とし、照らした範囲の後ろに glow を置く
- 線は SVG、文字は百分率で重ねた HTML。SVG は `aria-hidden` にし、文字を中に置かない。
  文字が lint と読み上げに残る。SVG の `viewBox` と重ねる箱の縦横比を揃えないと、ノードと線がずれる
- Before と After は同じ座標に重ねる。古いものは後ろに灰の実線の札で置き、新しいものを前に出す。
  何が起きたか（継がれた、足された、反証された）は小さな札で添える
- 締めは、話の始まりに出した図を同じ座標でもう一度出し、聞き手の番として中身を空ける。
  地と光は表紙に揃える。新しい図で締めると、着地せずに別の話へ開いて終わる
- 語は3層にする。見出しが主張、墨の帯が覚える一文、本文が根拠
- 点の比較（12 のうち 2 と、12 のうち 12）は `role="img"` と `aria-label` で数を言わせる。
  `<p>` に `aria-label` だけを付けると、読み上げに届かない

## 動き

- 動かすのは台本の動詞だけにする。集まる、辿る、照らす、積もる、閉じる、など
- keyframes は `from` だけを書く。止まった状態が完成した図になるので、PDF でも撮影でも崩れない
- 主線を先に描き、寄り道は遅らせる
- 循環は時計回りに順に出し、向きを教える
- 数値と火花は `.ts` の `draw(slide, { index, step, t })` で、`t` だけから描く。
  要素は `data-*` 属性で探す。クラスで探すと、見た目を直したときに動きだけが黙って止まる
- 到達点を先に置き、線が追いつくようにする
- ビートでは箱を保ったまま中身を出す。席を空けて見せてから埋める
- `marker-end` の矢じりは `stroke-dash` の動きに付いてこない。線を描き進めるなら、矢じりは別の要素にする
- 変形する要素の中に文字を置かない
- `.pop` の時間差は、並べる数だけ段を用意する

## dek での実装の要点

- `style=` は書けない。px の値は `.slide` の規則のカスタムプロパティにだけ置く。`var()` に代わりの値を書かない
- テーマのクラスには上限がある。変種はクラスを増やさず、`data-*` 属性で分ける（例: `.stage[data-stack]`）
- 使うクラスには、どこかに規則が要る。規則の無いクラスを目印に使わない
- 同じ宣言が複数の枚にあると警告になる。同じ意味ならテーマへ上げて属性で呼ぶ。
  名前が同じで意味が違うだけなら、名前を分ける
- スライドの CSS は、`theme.css` の末尾に書いたのと同じ重みで効く。
  `.stage` のようにテーマが `.slide[data-layout="…"] > .stage` で決めている箱は、スライドの CSS では上書きできない。
  中にもう1枚箱を置いて、そちらを組む（踏んだ）
- `aria-hidden` の下に字を置かない。装飾の SVG に `<text>` を入れると落ちる
- `data-morph` が効くのは隣の枚どうしだけ
- `dekc check` は1回に1枚。全体のはみ出しとコントラストは `dekc lint --visual` が1回で見る。
  `dekc check` が出す `fill` の `rows` と `columns` を見ると、画面の片側が空いた枚が絵を開く前に分かる
