# KOERU — コメントの書き方

言語を問わない。Rust の doc コメントでも、TSX の `{/* */}` でも、TOML の `#` でも同じ。

言語ごとの規約は別にある。Rust は [rust-conventions](../rust-conventions/SKILL.md)、React は [react-conventions](../react-conventions/SKILL.md)。

## 何を書くか

型と名前が言えるのは what。コメントが持つのは why。

- なぜそうしたか
- 何を試して駄目だったか
- どこで踏むか

この3つのどれでもないなら、たいてい書かなくてよい。

> 悪い例: `/// テイクの ID。` — `take_id: TakeId` の上
> 良い例: `/// 採用中のテイク。非採用も残るので、これは「今どれか」だけを指す。`

名前から読めることしか書けないなら、コメントを消して名前を直す。

### 踏んだことは書く

一度踏んだ落とし穴は、次に同じ場所を触る人が同じ形で踏む。何が起きたかを、抽象化せずに書く。

> `/// 1パス目は `final.alimdl`（話者非依存）。`final.mdl` は SAT で fMLLR 済みの
> /// 特徴を前提にしており、素の特徴に当てると尤度が歪む。踏んだ。`

## 何を書かないか

### 規則そのものを写さない

同じ規則を2箇所に書くと、片方だけが変わる（`AGENTS.md` の禁止事項6）。条件や数値の定義は meta 側に置き、コメントは ID で参照させる。

> 悪い例: `// F0 推定は SwiftF0 を採用する。`
> 良い例: `// F0 推定の方針は `DEC-SYN-001` を参照。`

### 装飾しない

- 太字は、踏んだこと・直感に反すること・戻すと壊れることだけに使う。全部が太字なら、どれも太字でないのと同じ
- 罫線でコメントを囲まない。長い関数の中で段を切るなら `// ## 見出し` の1行にする
- 出力される文字列（`println!`、`assert!` のメッセージ、テストの説明）に Markdown の印を入れない。端末には `**` がそのまま出る

### 同じ文を繰り返さない

1つのファイルの中で同じ説明が3回出てきたら、それは定数か関数の doc に置くべきもの。

> `// マスターの時間軸で見る。書かれる WAV は常に 44100。` が1ファイルに5回
> → 定数 `MASTER_RATE_HZ` の doc と、モジュール冒頭の1行にまとめる

層をまたぐ複製も同じ。`TakeResult` → `TakeView` → `ipc.ts` と同じ説明を3回書かない。いちばん上流に書いて、下流は参照する。

## 要件を引用するときは `ID の「…」` の形で書く

`cargo xtask check-references` が、この形の文字列を meta の原文と突き合わせる。原文が変わって引用が古くなると落ちる。

```rust
/// 前後の無音を自由にする（`TR-ALN-09` の「前後の無音区間の長さを自由にする」）。
```

逐語で引けないときは、この形にしない。ID だけを置いて、言い換えは括弧の外に書く。

```rust
/// （`TR-SYN-01`。外部プロセスの起動もネットワーク通信も禁じている）
```

日本語の「」は引用にも強調にも使うので、`ID の` が前に付いたときだけ逐語引用とみなす、と決めてある。この規約が無いと、例示のつもりの「オフセットだけ直した」まで「原文に無い」と言われる。

## ID はバッククォートで囲む

`TR-REC-06` ではなく `` `TR-REC-06` ``。rustdoc と TSDoc がコードとして描き、grep でも拾いやすい。

## 文体

- 日本語。英語と混ぜない
- 「〜すること」ではなく「〜する」。規約の条文ではなく、コードの説明として書く
- 1文を短く切る。読点で3つ以上つながったら分ける

## 検証

```bash
cargo xtask check-references   # 引用が原文と一致しているか
```

太字の量、罫線、重複は機械で見ていない。レビューで見る。
