## 受け継いで、問い直す — KOERU Design System {#cover}

KOERU に新しく加わる人に、KOERU がどうやって作られているかの仕組みを渡したくて、この資料を作りました。

仕組みの名前は KOERU Design System です。ただ、ふつう Design System と聞いて思い浮かべるものとは、少し違います。

> 背景に薄く敷いてあるのは、3章で何度も出てくるグラフ。ここでは説明しない。

## 規則で縛らず、放っておかず、文脈を敷く {#thesis}

結論を先に言っておきます。

規則で縛ると、判断は人の中で死にます。何も残さなければ、毎回ゼロから始まって、うまくいくかは運任せになります。

KOERU が歩きたいのは、その間の細い道です。文脈を敷く。

### 誰でも、気づいて変えられるように {#thesis-why}

受け継いだ判断で作り続けながら、それが合わなくなったら、誰でも気づいて、変えられるようにする。そのための仕組みの話です。

## KOERU は、波長の合う Creator に開いた OSS {#koeru}

KOERU は、UTAU の歌声ライブラリを、録音から配布まで一つの場所でつくるスタジオです。そして OSS です。誰でも読めて、直せて、配れます。決めたことの理由と、まだ分かっていないことまで、公開しています。

KOERU が求めているのは、経験豊富な UI/UX デザイナーではありません。UTAU が好き、ボカロが好き、DTM が好き、歌うのが好き。KOERU の技術や、デザインの考え方に興味がある。そういう、KOERU の文脈と波長の合う Creator です。デザインの専門家である必要はありません。

それから、中心メンバーを固定することを前提にしていません。いつでも入れて、いつでも出られて、いつでも戻ってこられる。特定の誰かに頼らないように作っています。

### 誰かが抜けても {#koeru-punch}

誰かが抜けても、判断の理由は残る。この資料は、そういう人たちが判断に加われるようにする仕組みの話です。

## 1　カタログの先 {#ch1}

まず、ふつうの Design System が何を持っていて、何を持っていないかを見ます。

## Design System は、ふつうトークンとカタログでできている {#catalog}

Design System と聞くと、多くの人はこれを思い浮かべます。色や余白の値、つまりトークンと、ボタンやカードのような部品を集めたカタログです。

色には段があって、段ごとに意味が決まっています。部品には、使い方の例が付いています。

### KOERU にもある {#catalog-koeru}

KOERU にも、これはあります。色の段の意味は決まっていて、部品は自分の見た目を自分で持ち、読みやすさは実際のブラウザで測っています。ここまでは、どこの Design System にもあるもので、KOERU もこれを大事にしています。

## カタログは楽譜。どう鳴らすかは書いていない {#score}

カタログは、楽譜に似ています。楽譜は、その場にいない人に音楽を手渡すための形式です。死んだ記録ではなく、演奏を起動できる。

でも、楽譜に書いてあるのは「どう作るか」までです。なぜそう決めたのか。どこまでの話なのか。何が起きたら覆すのか。誰が、何で確かめたのか。まだ分かっていないことは何か。この五つには、カタログは答えません。

### 演奏を起動できる {#score-punch}

楽譜は鳴らない。でも、演奏を起動できる。だから、楽譜に何を添えれば、次の人がちゃんと演奏できるかを考えます。

## 途中の選択が、いつのまにか「当然の制約」になる {#slip}

楽譜だけを手渡すと、何が起きるか。

ある場面で、誰かが一つの案を選びます。その結論が記録されます。次の人は、結論だけを受け取ります。そうするうちに、選択だったものが、前提に変わっていきます。

一手ずつは、どれも合理的です。それでも、終わりのほうでは理由が抜けています。比喩をきれいに成り立たせるために、体験のほうを組み替えてしまうことさえあります。

### 誰も悪くない {#slip-nobody}

誰も悪くありません。受け継ぐ道が太くて、疑い直す道が細いだけです。

## 規則を足すたびに、判断は人の中から消えていく {#dsloop}

細い道のままにしておくと、ずれが出ます。ずれを減らしたくて、規則を足します。外れは減ります。判断しなくてよくなります。すると、規則に合わない現実に気づけなくなって、またずれが出て、また規則を足します。

考えなくていい仕組みは、考えない人をつくります。目的が管理に置かれると、成功は「外れが無いこと」になってしまいます。

## 人を動かす方法は二つ。規則で結果を決めるか、判断の拠りどころを渡すか {#two-ways}

人に何かを手渡す方法は、大きく二つあります。

一つは規則です。たとえば「主な操作のボタンは、一画面に一つ」。もう一つは、判断の拠りどころを渡すことです。目的は、主な操作を一目で分けるため。良い例は、この画面。外れていいのは、同じ重さの操作が二つあるとき。

差が出るのは、規則が想定していない場面です。

### 判断の欄に写る {#two-ways-dec}

KOERU の判断の記録は、はじめから拠りどころの形で書かれています。選んだ理由、比べた案、覆る条件。この三つがあれば、次の人は、規則が想定していない場面でも自分で判断できます。

## Design System とは、判断に加われる文脈の総体 {#redefine}

だから KOERU では、Design System の意味を言い直します。

部品と規則の集まり、ではありません。異なる人が、良い創作の判断に加わり、直し、引き継げる条件。その文脈の総体を、Design System と呼びます。

### 育つ条件を保つだけ {#redefine-not}

これは、デザイナーを生産する装置ではありません。卒業もありませんし、成熟度の点数もありません。加わった結果として、設計の力は育ちます。でも、それを測って管理した瞬間に、育たなくなります。仕組みができるのは、育つ条件を保つことだけです。

## ビートを保ったまま、ずらす {#swing}

では、受け継いだ判断を、どう扱えばいいのか。音楽でいうスウィングに近いと考えています。

規則どおりに弾くと、拍の上から一歩も動きません。採ったから、確かめたことにしてしまう。でたらめに弾くと、拍そのものが消えます。確かめていないから、何も採らない。

スウィングは、拍を保ったまま、前後にずらします。採ったまま、まだ確かめていないと書いて、作り続ける。

### ふつうの状態 {#swing-states}

KOERU では、これがふつうの状態です。判断は採用されている。でも、その判断が依っている仮説はまだ確かめていない。だから、戻せる範囲で試す。

あるいは、仮説はある条件では支持された。それでも、守りたい価値と合わないので、判断としては採らない。

### 混ぜない {#swing-punch}

採用されているかどうかと、根拠があるかどうかを、混ぜない。これが、受け継ぎながら問い直すための、いちばん大事な区別です。

## だから、問い直す道を太くする {#answer}

受け継ぐ道は、放っておいても太くなります。だから、問い直す道のほうを、仕組みで太くします。

KOERU Design System は、そのための仕組みです。ここから、その全体を見ていきます。

## 2　全体像 {#ch2}

KOERU Design System が、どんな仕事でできていて、それぞれがどこにあるかを見ます。

## 一つのグラフを囲んで、十の仕事が回る {#whole}

KOERU Design System は、一つのループです。違和感を受け取る Signal。それを問いにする Question。問いから文脈を組み立てる Context。別の案を開く Design Space。読んで批評する Critique。確かめる Evidence。範囲を限って決める Decision。そして出荷する Implementation。

離れていた人が戻ってくる Re-entry と、仕組み自身を見直す System health も、このループの周りにあります。

### どこにあるか {#whole-where}

それぞれの仕事には、置き場所があります。違和感は GitHub の Issue に、問いはリポジトリの中に、文脈はコマンド一つで組み立てられます。案は Storybook の workbench に、確かめる道具と記録は検証の置き場に、判断は PR とリポジトリの中に残ります。

### グラフを読んで、書き足す {#whole-graph}

そして真ん中に、一つのグラフがあります。どの仕事も、このグラフを読んで、このグラフに書き足します。

### Agent は {#whole-agent}

Agent も、ほとんどの駅で手を貸します。問いの候補を出す、文脈の食い違いを探す、前提の違う案を作る、批評する、機械で確かめられるものを確かめる、実装する、戻ってきた人に変化を説明する。

約束は三つです。Agent は、人が頼んだときだけ動きます。出すのは、断れる形の候補です。そして Agent が止まっても、コマンドと Issue と人のレビューだけで、作業は続けられます。

Decision の駅にだけは、Agent がいません。採るのは、人です。

### 外の世界と {#whole-outside}

ループは閉じていません。違和感は外の世界から入ってきて、出荷された体験は外の世界へ出て、また誰かの違和感を生みます。

## 残す判断は、五種類の点と、型のある線になる {#graph}

真ん中のグラフを、もう少し近くで見ます。

点は五種類です。Q は、まだ答えていない問い。HYP は、起きると予想していること。EVID は、観測したこと。DEC は、当面こうすると決めたこと。REQ は、守らなければならないこと。

点と点は、型のある線で結ばれます。制約する、仮説に依る、観測を考慮する、前の判断を継ぐ、問いを閉じる、など。

### 三つの層 {#graph-layers}

このグラフには、三つの層があります。書き残す知識は、この五つの点です。使う資源は、確かめる道具や Storybook の story、PR、コミットで、グラフに吊るします。そして見え方。文脈や、人の確認待ちや、くり返し現れる形は、書き残しません。いつでもグラフから計算し直します。

### 残る意味だけが {#graph-flow}

出来事は Issue と PR に流れていきます。グラフに入るのは、残る意味だけです。点の ID は名前だけを持っていて、分類は持ちません。

## 見え方は、同じグラフの照らし方にすぎない {#projection}

見え方は、別々の資料ではありません。同じグラフの、照らし方の違いです。

問いから辿れる範囲を照らせば、Context になります。仮説と要求のどれに確かめる道具があって、何が走ったかを照らせば、検証の見取り図になります。人でしか確かめられない、まだ確かめていない仮説を照らせば、人の確認待ちになります。くり返し現れる形を照らせば、Pattern になります。

### 計算し直す {#projection-punch}

見え方を手で書き残さないので、古くなりません。このあと何度も、同じグラフが同じ位置に戻ってきます。

## 違和感は、正しい言葉を知らなくても持ち込める {#signal}

ここから、ループの駅を一つずつ見ます。最初は Signal です。

まだ言葉になっていない違和感を、そのまま受け取ります。原因は、最初から決めません。置き場所は GitHub の Issue で、どの版のどの画面かを添えてもらえれば十分です。

頼まれれば、Agent が観察と解釈と期待の分け方を候補として出します。ただし、違和感を勝手に別の問題へ言い換えることはしません。問いにする必要があるかは、人が判断します。

### 入口の問題にする {#signal-punch}

気づけるかどうかを、才能の問題にしない。入口の問題にします。

## 良い問いは、答えを埋め込まず、作るものを分ける {#question}

違和感を、判断を進められる問いにします。問いには、閉じる条件を持たせます。

良い問いには条件があります。答えを先に入れない。論点は一つ。誰が、どの場面で、を書く。症状ではなく、目指す状態に向ける。答え次第で、作るものが変わる。開く問いと閉じる問いを、段で使い分ける。

Agent は、既存の問いを検索して、重なりや不足を見つけ、問いの候補を少しだけ出します。既にある問いに書き足すほうを先に勧めます。問いに上げるかと、その優先度は、人が決めます。

### 開く問いと閉じる問い {#question-close}

開く問いは「何で伝えるか」「何が止めているか」のように、案を開きます。閉じる問いは「この案で見分けられるか」のように、確かめるときに使います。閉じる問いは、案を比べ終えてから、確かめる段で使います。

## Context は、問いから辿った、グラフの一つの射影 {#context}

問いが決まったら、その問いを根にして、グラフを辿ります。型のある線を、決まった規則で辿って、いま判断に要るものだけを集めます。同じ入力なら、いつでも同じ出力になります。

組み立てるのは、Agent ではなく決まった規則です。Agent は、孤立した点や、食い違い、古い前提を、出どころ付きの「要確認」の候補として返します。意味を勝手にまとめることはしません。

### 八つの項目 {#context-card}

出力は、八つの項目の要約になります。今回決めること、守る制約、現在案の理由、別案と採らなかった理由、弱まった前提、未解決の問い、見るべき作例、欠けている文脈。

人は、直前に見たものから次の判断を生みます。だから、最初に何を見せるかを、仕組みで決めて渡します。

## 本線を走りながら、寄り道で別の世界を見る {#design-space}

文脈が揃ったら、案を開きます。いまの案が本線です。本線に対して、前提の違う案を、寄り道として並べます。

変えるのは見た目ではありません。何が主役か、時間がどう進むか、誰が操るか、どう移動するか、何が先に見えるか。この五つのうち、どれかを変えます。

Agent に一度「案をたくさん出して」と頼むと、同じ前提の案がいくつも出てきます。だから、寄り道ごとに渡す文脈を変えて、別々に走らせます。制約だけを渡す。逆張りを頼む。他の分野を探させる。Agent が出すのは下書きまでです。よくできた試作でも、使う人が支持した証拠にはなりません。

### 比べた跡 {#design-space-punch}

寄り道は消えません。比べた跡として、PR の履歴に残ります。

## 読んでから、意図を明かす {#critique}

作った案は、まず意図を伏せて読んでもらいます。黙って見せる。読み取ったことを書いてもらう。そこで意図を明かす。意図と読みのずれを見る。それから批評して、必要なら問い直します。

コメントは、対象、観察、解釈、関係するもの、次に試すこと、の五つの欄で書きます。役は輪番で、作者、読み手、逆張り役、文脈の番人、調べ役があります。

Agent は、版を固定した作例をブラウザや試験で開いて、補助の批評を出します。道具で観測したことと、自分の推論は分けて書きます。読み手の席には座りません。

### 作ったものを批評する {#critique-punch}

批評するのは、人ではなく、作ったものです。

## Probe はグラフに吊るす道具。走らせた跡が Receipt {#probe}

確かめたい仮説には、Probe を吊るします。Probe は、何を、どの条件で走らせれば観測できるか、という約束です。自動の試験もあれば、画面の操作の試験も、実機のハーネスも、人に見てもらう手順もあります。

走らせると、Receipt が残ります。何件見つけて、何件走ったかの記録です。

Agent は、仮説の種類から使ってよい Probe を選んで、機械で走るものを走らせます。人でしか確かめられない仮説には、作った答えを返さず、未解決のまま人の確認待ちへ送ります。

### 走ったことではない {#probe-punch}

Probe があることは、走ったことではありません。

## 観測は、確かめる資格のある問いにだけ証言できる {#evidence}

観測したことは、Evidence として残します。ただし、方法ごとに、どの種類の仮説に証言できるかが決まっています。証言できる、できない、仮説を生むだけ、条件しだい、の四つです。

Agent が走らせた試験の結果は、試験の観測として Evidence になりえます。でも、Agent が使う人になりきって語った感想は、Evidence になりません。

### 洗い流さない {#evidence-rules}

確かめていないものが、いつのまにか確かめたことになるのを防ぐ規則が五つあります。出所と解釈を分ける。件数を確信に変えない。方法の資格を超えない。反証も同じ面に出す。走ったか、飛ばしたかを書く。

## 人にしか確かめられないものは、積もる。だから見えるようにする {#debt}

人でしか確かめられない仮説は、どうしても積もります。だから、いつでも取り出せる一覧にします。人に会える一回の機会を、いちばん情報の多い観察に変えるための計画面です。

一つの点数にはしませんし、減らすこと自体を目的にもしません。積むのも外すのも、グラフの関係から機械的に決まります。Agent は、一度の観察でまとめて確かめられる仮説の組を、候補として示せます。架空の人物を作って、参加者として記録することはしません。

### 同じではない {#debt-punch}

人に会えないことと、何も出せないことは、同じではありません。

## 判断は、範囲と、覆る条件ごと残す {#decision}

判断は、範囲を限って選びます。覆る条件は、観測できる形で書きます。異議には、五つのどれかで応えます。対応した。条件を限定した。残るリスクとして引き受けた。別の問いへ移した。採らない理由を説明した。

前の判断は上書きしません。新しい判断が、前の判断を継ぎます。

Agent は、ここにはいません。判断を採ることも、PR を承認することもできません。お願いで止めているのではなく、権限で塞いであります。覆る条件に触れる観測が入ったことは、決まった規則の見張りが知らせます。

### 言い直せる回路 {#decision-punch}

あとから言い直せる回路を、開けておきます。

## 出荷は、確かめた範囲と戻し方を添えて {#ship}

採った状態は、Storybook の stable に移して、出荷します。比べた試作は PR の履歴に残して、本体には混ぜません。

PR には、四つの欄を書きます。設計上の変更、体験の差、確認した範囲、戻し方。CI は、参照と仮説と、どこまで走らせたかを検査します。

Agent は実装してかまいません。人と Agent のどちらが書いたかで、扱いは変えません。統合して出荷するかは、人が決めます。

## 離れて、変わって、戻ってくる {#reentry}

KOERU には、ずっと居続ける必要はありません。離れるときは、いまの版と次の一手を、三点だけ残します。

戻ってきたら、離れた時点といまを比べた文脈を出します。いま何が有効か。その間に何が変わったか。同じ出力で見られます。

Agent は、この比べた出力を読んで、確かめたほうがいい箇所を説明します。あなたが何を覚えているはずか、を推し量ることはしません。

### 入れ直しではない {#reentry-punch}

外で変わった見方は、新しい Signal になります。復帰は、正しい文脈を入れ直すことではありません。

## 仕組み自身も、問い直しの対象になる {#health}

最後に、仕組み自身も見直します。戻ってくるのにかかった手間、異議を出せたか、費用、使われていない仕組み、削れる候補。仕組みを減らす提案も、Signal として入ってきます。

Agent は集計を手伝いますが、仕組みがうまくいっているかの判定役にはしません。

### 削る {#health-punch}

足すだけでなく、削ります。

## 3　一周してみる {#ch3}

ここからは、ある一行の違和感で、このループを一周してみます。

届いた一行は、「声の環、なんかビミョい」。

## 声の環：中心で声が育ち、まわりの環が閉じていく {#ring}

まず、声の環を説明します。KOERU で、音源がどこまで録れているかを見せる図です。

中心に、育っていく声がいます。そのまわりに、五十音の行ごとの環が重なっていて、録れた分だけ、弧が閉じていきます。色は、その声から生まれます。

点数や良し悪し、ほかの音源との比較は出しません。録れた量と、いま歌える曲の数を、いつも両方見せます。

## ある日、Issue に一行が届く {#ex-signal}

ある日、Issue に一行が届きます。「声の環、なんかビミョい」。添えられているのは、版と、音源の一覧の画面です。

正しい言葉は要りません。原因も、最初から決めません。

## まず、観察と解釈と期待に分ける {#ex-separate}

まず、この一行を三つに分けます。

観察。一覧で、録れた量が 14% の音源と 100% の音源が隣に並んで、環の外径が三倍違った。解釈。大きいほうが「上」に見える気がした。期待。一体ずつ、違う育ち方をしている声として見たい。

### Agent に頼む {#ex-separate-agent}

報告した人が、Agent に問いの枠組みを頼みます。Agent は、候補を二つ返します。観察が一つ足りません、何体並んだ一覧で、どの音源が隣でしたか。それと、似た問いはまだありません。

報告した人は、一つ目を採って、観察に書き足しました。Agent は分け方を手伝いますが、何がビミョいのかは、報告した人の言葉のまま残ります。

## 答えを入れずに、何を作るかが分かれる形で問う {#ex-question}

次に、問いにします。Agent が、問いの候補を三つ出しました。

人が、問いの条件と突き合わせます。「環の外径を揃えるべきか」は、答えが入っているので落とします。「環は、比較に見えるか」は、誰が、どの場面で、が無いので落とします。「一覧で、録れた量を何で伝えるか」は残します。ただ、場面が足りません。

そこで、場面を書き足します。一覧から次に開く音源を選ぶ人に、それぞれの音源がどこまで録れているかを、何で伝えるか。一覧では伝えない、も含めて。

閉じる条件は、案を比べて、選んだ理由と残るリスクを判断に書いたとき、です。

### 仮説は別の欄へ {#ex-question-hyp}

問いの中に混ざっていた予想は、仮説として別の欄に移します。初めて見る人は、外径の差を、優劣ではなく録れた量の差として読む。まだ確かめていません。

Agent の候補は、断れる形で届きます。どれを採って、どう直すかは、人が決めます。

## 危険の大きさで、進め方の道を選ぶ {#ex-lane}

進め方を決める前に、この変更がどのくらい危ないかを見ます。戻せるか。権利や害に触れるか。根拠がどれだけ欠けているか。操作がどれだけ新しいか。影響がどこまで広いか。移行にどれだけかかるか。

この変更は、戻せて、害はなく、根拠は欠けていて、新しさは中くらい、影響は一覧だけ、移行は軽い。

### 戻せるが、まだ確かめていない {#ex-lane-r1}

だから、いちばん軽い道を選びます。戻せるけれど、まだ確かめていない。未検証と書いたまま、範囲を限って試してかまいません。

## 問いを根にして、文脈を組み立てる {#ex-context-cmd}

問いを根にして、文脈を組み立てます。コマンドを一つ打つだけです。出てくるのは、さっきの八つの項目です。

この出力が何を辿って作られたかを、グラフの上で見てみます。

## まず、守っている規範を辿る {#ex-graph-1}

問いから、いまの判断へ辿ります。いまの判断は、中心に育っていく声を置いて、一覧でも外径を録れた量に比例させる、というものです。

この判断を、二つの規範が縛っています。点数や比較を出さないこと。録れた量と歌える曲の数を、いつも両方見せること。

## 次に、判断が依っている仮説と観測を辿る {#ex-graph-2}

判断は、二つの仮説に依っています。外径の差は、録れた量の差として読まれる。環は、自分の声との関係を助ける。どちらも、まだ確かめていません。

そして、一つの観測を考慮しています。実機の一覧で、外径が三倍違った、という観測です。

### 資格の食い違い {#ex-graph-2-gap}

ただ、この観測は描画を測ったものです。どう描かれるかには証言できますが、どう読まれるかには証言できません。

文脈の点検を頼まれた Agent が、出どころ付きで候補を返します。この判断は、資格の合わない観測で仮説を支えている可能性があります。食い違いを見つけるのは Agent でもかまいません。それが本当に食い違いかを決めるのは、人です。

## 判断に書いてあった「覆る条件」に、いま触れている {#ex-graph-3}

いまの判断には、覆る条件が書いてありました。環の外径の差が、一覧で音源どうしの比較として読まれていると分かったとき。

「大きいほうが上に見える」という一行は、まさにこの条件に触れています。

### 見るべき作例と、欠けている文脈 {#ex-graph-3-edge}

見るべき作例として、一覧の story が照らされます。そして、まだ無いものも見えます。初めて見る人が、どう読むかの観察です。

## 八つの項目の要約で、判断の足場ができる {#ex-context-card}

八つの項目を埋めると、こうなります。

今回決めるのは、一覧で録れた量を何で伝えるか。守る制約は、比較を出さないことと、録れた量と歌える曲を両方見せること。いまの案の理由は、育っていく声が一覧でも見えること。外径を揃える案は、あ行から外へ育つ読み方を失うので、残るリスクとして引き受けていました。弱まった前提は、外径の差が録れた量として読まれること。未解決の問いは、一覧がどんな場面で何のために開かれるか。見るべきは一覧の story。欠けているのは、初めて見る人の読み方です。

この要約は、決まった規則が組み立てたものです。Agent は書いていません。

## 本線の現在案と、前提の違う寄り道を並べる {#ex-space}

足場ができたので、案を開きます。本線は、外径を録れた量に比例させる、いまの案です。

寄り道は五つです。A、外径を揃えて、閉じ具合だけで示す。B、まだ録っていない行を、薄い軌道として先に描く。C、一覧では形だけを見せて、量は開いた先で出す。D、キャラクター選択画面のように、同じ大きさの枠に立たせる。E、協力者のスケッチ。

### Agent の寄り道 {#ex-space-agent}

A と C と D は、Agent が作りました。三つは別々に走っていて、互いの案を見ていません。

A には、制約と場面だけを渡しました。いまの案も、これまでの判断も渡していません。C には、いまの案を渡して、この案が前提にしていることを一つ壊して、と頼みました。D には、他の分野で、同じ重さで並べて一つを選ばせる画面を探させました。

Agent はそれぞれ、操作の流れと、予測する差と、反例と、要る観察を添えて、試作を下書きで返しました。B と E は、人が作りました。

### 証拠にはならない {#ex-space-punch}

よくできた試作でも、使う人が支持した証拠にはなりません。

## 見た目の違いと、世界の違いを分ける {#ex-variation}

五つの案を、さっきの五つの次元で比べます。A と B は、何が先に見えるかだけが違います。これは同じ世界の変奏です。C と D は、何が主役かと、どう移動するかを変えています。別の世界です。

### 数え方 {#ex-variation-audit}

差の表は、Agent が下書きしました。数え方を決めるのは人で、A と B を一つの世界にまとめました。前提の差を書けない案は、別の案に数えません。

## 作者は黙って、読み手が先に読む {#ex-blind}

案 B を、意図を伏せて読んでもらいます。

読み手は言いました。全部が同じ大きさの器に見える。でも、空いているところが「足りない」と言われているようで、少し苦しい。

### 意図を明かす {#ex-blind-reveal}

そこで、作者が意図を明かします。育つ先がもう用意されている、と感じてほしかった。

意図と読みの間に、ずれがあります。空きが、足りなさの圧として読まれました。

Agent にも読ませることはできます。でも、その読みは仮説を生むだけです。人の読み手の席は、Agent では埋めません。

## 批評は、五つの欄で書く {#ex-comment}

この読みを、批評のコメントにします。対象は、案 B の一覧で、14% と 100% を並べた状態。版は固定しています。観察は、軌道の空いた部分に、先に目が行ったこと。解釈は、足りなさを示されているように読めたこと。関係するのは、足りなさは「あと何を録れば、何が歌えるか」の形で示す、という制約。次に試すのは、軌道を線ではなく、ごく薄い面にした版です。

### 逆張り役 {#ex-comment-roles}

逆張り役は、別の角度から問います。外径を揃えると、一覧で音源を見分けにくくならないか。

### Agent の批評 {#ex-comment-agent}

Agent の批評も、同じ五つの欄で並びます。ただし、欄の中を、観測と推論に分けます。観測。ブラウザで描画を開くと、軌道の線のコントラストは、地に対して 1.6 対 1 だった。推論。線が薄いので、空きが「無い」より「まだ」に見えやすいかもしれない。

## 確かめたい仮説に、Probe を吊るす {#ex-probe}

確かめたい仮説に、Probe を吊るします。初めて見る人は、外径の差を、録れた量の差として読むか。これは初めて触れる人でないと確かめられません。

予測は、外径の違いを、録れた量の違いとして説明すること。反証は、優劣として説明するか、差に気づかないこと。

もう一つ、機械で確かめる Probe も吊るします。描画と、焦点と、状態の移り変わりを見て、録れた量と歌える曲が両方見えているかを確かめます。

### 道を分ける {#ex-probe-agent}

確かめる役の Agent が、仮説の種類を見て道を分けます。機械で確かめられるほうは、Probe を選んで走らせます。読み方のほうは意味の理解なので、作った答えを返さず、人の確認待ちへ送ります。

## Receipt は、何が走り、何が走らなかったかの記録 {#ex-receipt}

走らせた跡が、Receipt です。機械のほうは、八件見つけて、八件走って、通りました。走らせたのは Agent です。

人のほうは、協力者がまだいないので、走っていません。この欄は、Agent が埋めることはありません。

### 資格を超えない {#ex-receipt-punch}

Receipt は、Probe の資格を超えることを証明しません。

## 観測を、言えることの範囲で残す {#ex-evidence}

機械の Probe から、新しい観測が残ります。揃えた環でも、各行の閉じ具合は、描画の上で見分けられる。これは見え方について証言できます。でも、読まれ方については証言できません。だから、読み方の仮説は、まだ確かめていないままです。

### 誰が走らせたかではなく {#ex-evidence-blind}

さっきの、仲間に読んでもらった結果も、初めて触れる人の読みではないので、仮説を生むだけです。Agent の読みは、証言できません。一方で、この観測は Agent が走らせた試験から出たものですが、証言できます。

誰が走らせたかではなく、何を観測したかで、資格が決まります。

## 確かめきれない仮説は、人の確認待ちに積もる {#ex-debt}

確かめきれなかった読み方の仮説は、人の確認待ちに積もります。一覧には、それが意味の理解についての仮説であること、どの判断が依っているか、戻せること、一度の観察で一緒に見られる仮説、使う Probe が並びます。

人に会えたら、一回の観察で、これをまとめて確かめられます。

## 範囲を限って採り、前の判断を継ぐ {#ex-decision}

ここで判断します。一覧では外径を揃えて、行の閉じ具合で示す。音源の画面では、これまでどおり外へ育つ。

比べて採らなかった案は、C は一覧で量が分からず続きを選べないから。B は空きが足りなさの圧として読まれたから。この判断は、揃えた環でも録り途中の音源を見分けられる、という仮説に依っています。まだ確かめていません。覆る条件は、初めて見る人が、揃えた環を区別できないと分かったとき。

### 前の判断を継ぐ {#ex-decision-graph}

グラフの上では、新しい判断が、前の判断のうち一覧の表し方の部分を継ぎます。前の判断は消えずに、継がれたものとして残ります。そして、新しい規範が一つ生まれます。一覧では、環の大きさで録れた量を表さない。

### 異議に応える {#ex-decision-objection}

逆張り役の異議には、残るリスクとして引き受けて、覆る条件に入れた、と応えます。

この判断の欄に、Agent は書けません。採るのは、人です。

## PR には、体験の差と、確かめた範囲と、戻し方を書く {#ex-pr}

PR を出します。設計上の変更は、一覧の環の外径を揃えて、閉じ具合で示すこと。体験の差は、並べても大きさで序列が生まれず、録り始めの音源も小さく見えないこと。確認した範囲は、描画と焦点と状態の移り変わりは自動で確認した。初めて見る人の読み方は未確認で、人の確認待ちにある。戻し方は、一覧の表し方を一つ戻せば、比例の表示に戻る。

比べた案は PR の履歴に残って、採った状態だけが stable の story へ移ります。

### 誰が何をしたか {#ex-pr-agent}

実装と、この四つの欄の下書きは Agent がしました。確認した範囲は、Receipt から写しています。CI が検査して、人が下書きを直し、統合して出荷します。

「初めて見る人の読み方は未確認」という行は、Agent には消せません。

## 一周したあと、グラフはこう変わった {#ex-after}

一周したあと、グラフを、一周前と比べます。足されたのは、新しい判断と、新しい規範と、Probe と、新しい観測と、新しい仮説。前の判断は、一覧の部分が継がれました。問いは閉じました。

### 確認待ちの入れ替わり {#ex-after-debt}

人の確認待ちからは、外径の読み方の仮説が消えました。確かめたからではありません。判断が、もうそれに依っていないからです。代わりに、揃えた環で見分けられるか、という仮説が入りました。減らすことを、目的にはしません。

### 戻ってきた人へ {#ex-after-reentry}

数か月離れていた別の人が戻ってきたとき、Agent はこの差分を読んで、三行で説明します。いま有効なのは、一覧は揃えた環で、音源の画面は外へ育つまま。変わったのは、一覧の表し方の判断が継がれたこと。確かめたほうがいいのは、新しい判断が、まだ確かめていない仮説に依っていること。

## 残ったのは、規則ではなく、設計の手 {#ex-learn}

この一周で残ったのは、規則ではありません。設計の手です。量を何で表すかは、並べたときに何が読まれるかから決める。空いている場所は、足りなさとしても読まれうる。

これを規則にはしません。くり返し現れたら、Pattern の見え方が候補として示します。Agent は候補に名前と説明と反例を付けられますが、元の判断を消して、一つの原則に置き換えることはしません。

### 次の誰かの文脈 {#ex-learn-next}

この一周が、次の誰かの文脈になります。

## ここまで：楽譜、ループ、照らし方 {#recap}

ここまでをまとめます。カタログは楽譜で、どう鳴らすかは書いていない。だから、判断を理由ごと残して、問い直すループを回す。そして見え方は、一つのグラフの照らし方として、いつでも計算し直す。

## 4　あなたへ {#ch4}

最後に、あなたの話をします。

## 最初の一手は、違和感を一行書くこと {#first-step}

全部を担える人は、ほとんどいません。でも、最初の一手なら、ずっと多くの人が出せます。

最初の一手は、違和感を一行書くことです。正しい言葉は要りません。解決まで担わなくてかまいません。一回の発見、一つの修正、短い再参加。どれも、参加です。

## 読み手として、逆張り役として、番人として、調べ役として {#roles}

加わり方はいろいろあります。作者として案を出す。読み手として、意図を知らずに読む。逆張り役として、別の角度から問う。文脈の番人として、受け継いだ判断を思い出させる。調べ役として、外の知識を持ち込む。

役は輪番です。肩書きにはしません。

## 加わる自由と同じだけ、加わらない自由がある {#freedom}

KOERU には、加わる自由と同じだけ、加わらない自由があります。問いを持ち込む入口があり、自分で作る場所があります。記録しない自由、離れて変わる自由、AI の案を拒む自由、そして、公開しないまま完成させる自由があります。

### 管理で確実にしない {#freedom-why}

管理で確実にしようとした瞬間に、問い直しは死にます。だから、見張らない。点数にしない。離れる権利を奪わない。

## あなたの人生を、KOERU に持ち込んでほしい {#outside}

KOERU の Contributor は、KOERU の文脈の外で生きています。

誰かの声を好きになったり、誰かの曲に心を動かされたり、自分もやってみたいと思ったり、でも自分の声はちょっと恥ずかしいなと思ったり。試してみたい技術を見つけたり、新しい人に出会ったり、誰かと一緒に何かをつくったり。

その一つ一つの経験の連なりが、あなたの人生です。それを、KOERU に持ち込んでほしい。

### いろんな視点から {#outside-bring}

人の視点は、あまりに多種多様です。だからこそ、いろんな見え方が生まれます。KOERU をいろんな視点から見ることに、ほかでもないあなたに加わってほしい。

### どんなに小さくても {#outside-small}

そこで生まれた Signal がどんなに小さくても、KOERU Design System と KOERU Contributors は、KOERU を問い直します。

## まずは、あなたの Signal を教えて {#your-signal}

3章は、Issue に届いた一行から始まりました。「声の環、なんかビミョい」。

次の一行は、あなたのものです。正しい言葉は要りません。版も画面も、分からなくていい。原因も、決めなくていい。

まずは、あなたの Signal を教えて？

> 3章の始まりと同じ Issue の札を、同じ位置に、中身を空けて出す。地と光は表紙と同じにする。角のループの印は Signal に戻っている。
