# KOERU — Vision & Concept

## One-line statement

> **声を、誰もが手渡せる創作物にする。**

## Concept

**Why** — AI によって、誰もが歌声を生成できる時代になった。だから今問われているのは「作れるか」ではなく、その声を誰が持ち、どう創作へ手渡せるかだ。UTAU は、声をファイルとして持ち、配り、知らない誰かがそれで新しい作品を作る文化をつくった。一方でその入口は、覚える理由のない用語と、4つ以上に分断された工程のまま残っている。

**Who** — UTAU 文化に愛着を持ちながら今の制作環境に不満を抱えている既存クリエイターと、関心はあるのに何らかの理由で入口に立てていない新規クリエイター。両者に共通するのは、声を録りたいだけなのに工程を跨がされていること。そして UTAU 文化を愛していること。

**What** — KOERU では、短いフレーズを録るだけで、録り終える前に自分の声が歌い出す。そこから声は歌える範囲を広げ、自分の手元に残る形のまま、誰かの創作へ渡っていく。

**How it's different** — RecStar は録音を、OpenUtau は歌わせることを、ACE Studio は高品質なモデルを良くした。KOERU が中心に置くのはそのどれでもなく、自分の声が新しい存在になったと本人が感じ、それを他者へ手渡せること。声はベンダーに預けるモデルではなく、本人が所有し、持ち運び、渡せる創作資産として扱う。

## Three Principles

一行ステートメントは北極星であり、それ自体は日々の意思決定を切る制約を持たない。判断基準はこの3原則が担う。

- **Create before configure** — 設定する前に、まず歌える
- **Own your voice** — 自分の声は自分のもの
- **Made to be handed on** — 手渡せる状態まで、つくる

## Scope

引き受ける痛みの優先順位。

| 痛み | 扱い |
|---|---|
| 分断（工程を跨ぐこと自体） | **最優先で背負う** |
| 専門用語（意味が分からないこと） | ある程度背負う |
| 環境（録音機材・場所がないこと） | 背負わない。**要件として外に置く**（下記） |
| 動機（始める理由・終える理由） | 背負わない |

録音条件の前提。

- **ある程度の品質のマイクを持っていることを前提とする。** イヤホンマイクでも構わない。専用の録音機材は要求しない。
- **通常の声量で発声できることを前提とする。** 小声での収録は想定しない。
- したがって、調査で最多の障壁だった「録音機材や場所がない」46.0% のうち、**機材をまったく持たない層と、声を出せる場所を確保できない層は、初期の要件を満たさない。** 環境を背負わないという判断の帰結として、ここは解決する問題ではなく前提として外に置く。

手渡しの範囲と完成の定義。

- **手渡しは配布パッケージ（ZIP）の生成まで。** 配布の場・音源の発見機能は持たない。UTAU の分散型配布文化を壊さず、規約・権利・モデレーションを背負わない。手渡しの先は製品の外にあるため、**Made to be handed on が製品機能として意味するのは、渡せる状態をつくるところまで**であり、渡った先で何が起きるかを製品は関知しない。
- **非公開のまま完成できる状態を、正規の完成形として残す。** 完成の基準は「手渡せる状態になったか」であって、「実際に誰かへ渡したか」ではない。**公開したかどうかを、完成度や進捗の判定に使わない。**
- **起動直後の画面はプロジェクト作成。** 入口の構造は既存制作者に合わせ、案内は新規制作者に合わせる。オンボーディングで、どこまで作るかの選択肢が新規層にも分かるようにする。
- **方式（単独音 / 連続音 / CVVC / 多音階）は最初に選ぶ。選択肢は「手作業が必要かどうか」を主軸に見せる。** 「全自動で完結する」「確認作業はあるが音質が良い」「作り込む」という切り方にし、所要時間は併記するが主軸にしない。理由は、単独音と CVVC の録音時間差が1.7分程度しかなく時間では選択肢が並ばない一方、**自動原音設定が全自動で完結する見込みがあるのは単独音だけ**で、そこが利用者にとっての実質的な違いになるため。選択を先送りするのではなく、**選択のコストを開示する。**
- **ミニ音源は、選んだ方式の録音リストの先頭部分として存在する。** 録音リストは KOERU が内部生成するので、**先頭から順に録ると早い段階で歌える曲が現れるように並べ替える。** 課題曲と録音リストを同時に設計する必要がある。
- **原音設定は自動を既定とするが、setParam / vLabeler と同等の編集機能を必ず持つ。** 人間の編集可能性を残す。通常モードで用語を出さないことと、上級者が数値を直接触れることは両立させる。
- **書き出す WAV のファイル名は ASCII 固定。** 読み込みは日本語ファイル名にも対応する。NFD 正規化、大文字小文字だけが違う重複、CP932 で表現できない文字という3種の破綻を、書き出し側で構造的に起こさないため。
- **周波数表（`.frq`）は録音時に作る。** 即時試唱のための F0 解析がどうせ走るので、その副産物として書き出す。
- **録音直後の前処理（ハイパス / ノイズ低減 / 正規化、既定オフ）は、試唱と配布に同じく適用する。** 本人が確認した音と手渡した音を一致させる。マスターは不変で保持し、設定を変えればいつでも再生成できる。

実装の形。

- **ライセンスは AGPL-3.0。** OSS として公開し、外部からの Issue と PR を受け付ける。DCO を導入する。コピーがクローズドソースの製品になることを防ぐため。
- **KOERU は単一のネイティブアプリケーション。** ユーザーは PC を持っていることを前提とする。**実装は Rust + Tauri。**
- **配布は直接ダウンロードを主経路とする。** Microsoft Store の標準ライセンス条項は GPL 系と整合しないため、Store 経路は取らない。Windows は WebView2 を固定バージョンで同梱して環境依存を排除し、Linux は Flatpak の1形態で配布する（WebKitGTK のディストリビューション依存を runtime に吸収できるため）。
- **処理はローカルで完結させる。** 声をサーバへ送らない。Own your voice を実装レベルで守る。
- **まず UTAU エコシステムをサポートする。** そこから外れる形式（NNSVS / ENUNU / DiffSinger 系のニューラル音源データセット）は初期のサポート対象外とする。
- **合成は WORLD（BSD-3-Clause）を基礎とする。** ニューラルボコーダへの置き換えは採らない。ユーザーの声でモデルを学習・適応させることになり、**「あなたの声そのもの」が「生成された声」に変わる**ため、思想の中核が別物になる。ただし部品ごとの差し替えは行い、**F0 推定は SwiftF0 を採用する**（学習コーパスのライセンス監査を前提条件とし、非商用限定が含まれていれば WORLD の Harvest に戻る）。
- **アクセシビリティは既定で満たす要件として扱う。** 選択的な追加機能ではない。
- **利用計測はオプトインで行い、自前サーバーを持たない。** クラッシュ・例外は SaaS 経由で受け、GitHub Issue の自動起票からエージェントによる修正 PR、Core Contributor のレビューという継続開発サイクルに乗せる。到達率・離脱地点は人がダッシュボードで見る。**送信フィールドはホワイトリスト方式**とし、音源名・ファイルパス・歌詞・プロジェクト名を送らない。
- **UI の多言語対応は初期スコープ外。** 日本語のみで始める。
- **プロトタイプ検証のフェーズは置かず、最初から本番として実装する。**

## まだ決めていないこと

- **方式ごとの所要時間** — 主軸から外したので判断材料としての比重は下がったが、併記する数値は要算出。単独音 約8分、多音階連続音 約3時間は目安に過ぎず、その間にある方式の値は出ていない。
- **選んだ方式から上位方式へ移る経路** — 単独音で作った人が後から連続音に拡張する場合、必要な素材は追加録音になる（既存素材からの変換はできない）。この経路を用意するかは未決。用意する場合、**セッションをまたいだ録音の声質不連続**が問題になる。
- **JTBD の分布** — 「声が歌うのを聴きたい / キャラクターを作りたい / 他人に使ってほしい / 自分の曲を歌わせたい」の比率が不明。調査は「作るか / 作らないか」しか聞いていない。
- **オンボーディングの具体設計** — 音源の名前を後から変えられるか、仮名で始められるか。「全自動で完結する / 確認作業はあるが音質が良い / 作り込む」をどう言葉にするか。
- **日本語アライメントモデルの最終選択** — Julius を本命とするが、同梱される `.binhmm` 音響モデルへのライセンス適用が文面上は明示されていない。気になる点として記録した上で進める。実測精度も未確認。
- **SwiftF0 の学習コーパス監査** — 重みは CC BY 4.0 だが、学習データに MDB-STEM-Synth など非商用限定の可能性があるものが含まれる。採用の前提条件。

## Naming

**KOERU** = 「声」と「越える」。中心の意味は「制作のハードルを越える」ではなく、**声が、あなたを越えて創作へ向かう**こと。声は時間を、場所を、本人の表現を、技術方式を越えて、誰かの創作の中で再び歌う。

## Tone

大胆で理想を語る × 温かく人間的。ただし未来技術を誇示せず、ノスタルジーにも寄りかからない。「昔はよかった」ではなく「UTAU が生んだ声を手渡す文化には、まだ未来がある」。ブランドの言葉には AI・音声合成・ライブラリ制作といった技術語を避け、**声・人・創作**の言葉で語る。
