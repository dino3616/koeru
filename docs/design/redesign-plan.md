# フロントエンドのリデザイン — 対応方針

ジャーニーマップとユースケースを洗い直し、OOUI で情報構造を組み直し、雰囲気をリブランドしたうえで、画面をゼロから作り直す。その順序と分担を決める。

このファイルは作業中だけ存在する。 Phase 6 の差し替えが済んだら消す。ここで決めたことのうち残すべきものは、その時点で `meta/decisions/` と `docs/design/` の常設文書へ移っている。

## なぜやるか

画面は2つしかない。 `/`（音源一覧）と `/record`（収録）で、収録画面が「マイク」「いま録るところ」「録れたもの」「録れたもの一覧」「歌える曲」の5枚を縦に積んでいる。画面名が動詞で、その下に性質の違うオブジェクトが同居している。

`docs/product-vision.md` が中核に置いているものに、置き場所が無い。 録る順の切り替え（曲バンク優先と被覆効率、可逆）、方式の選択、録音リストそのもの、持ち込んだ UST の集合。どれもオブジェクトとして扱われていない。`create_project` が受け取るのは表示名だけなので、方式選択は Rust 側にも無い。

一覧画面が「あとから変えられます」と書いているが、変える口が無い。 生成された commands に改名が無い。

ブランドが視覚に出ていない。 Radix の slate と cyan をそのまま使い、カードは1種類。`docs/product-vision.md` の Tone は文章にはあるが、画面には形が無い。だからリブランドの作業は、新しいブランドを発明することではなく、確定済みの Tone に視覚言語を与えることになる。

## 決めたこと

### 一次リサーチはやらない

デプスインタビューは行わない。 **したがって、この計画から出る JM・UC・OOUI はすべて未検証の仮説の上に載る。** `docs/journey-map.md` が冒頭に置いているのと同じ但し書きを、新しく書く文書にも残す。UC の確度は Assumption が主軸のままで、`Fact` へ上げられるのは調査 PDF の数値に直接対応するものだけ。

聞き取り無しでも事実として取れるものが3つある。ここを厚くして代替する。

1. 競合の情報構造。OREMO / RecStar / vLabeler / setParam / OpenUtau / ACE Studio を触り、オブジェクトとビューの構成を分解する。観察できるので `EVID-UX-*` に載る
2. 現行実装の棚卸し。全画面・全部品・全状態と `TR-*` の対応表
3. 公開されている制作の痕跡。制作記事、配布ページ、音源制作 wiki、制作実況。発話の引用ではなく「どこで詰まったと書いてあるか」という行動の痕跡を拾う。推測ではないので、現行 JM の `※推測` を何箇所か外せる

あわせて `Q-*` を1本立てる。「一次リサーチ無しで置いた仮説のうち、外れると設計が崩れるのはどれか」。M4 の出荷前に潰す候補として持つ。

### リブランドはロゴ・シンボルまで

名前 KOERU は据え置く。`docs/product-vision.md` の Naming と Tone を上位に置く。

### OOUI は M7 まで見る

M4（配布）、M5（方式拡張）、M6（原音設定エディタ）のオブジェクトまで含めて骨格を決め、まだ作らないものは席だけ空ける。後から差し込むと構造が壊れる。

`Q-PLT-004` は open で M6 を塞いでいる。描画面の性質に依存する部分は穴のまま残す。埋めようとすると、実測前の推測が構造に焼き付く。

### 別ブランチで作り直して差し替える

段階的な置き換えではなく、ゼロから組み直してから main へ入れる。

## フェーズ

### Phase 0 — 成果物の仕分け

正本の取り違えを防ぐため、書き始める前に置き場所を決める。

| 出てくるもの | 置き場所 |
|---|---|
| 観察できた事実 | `meta/evidence/EVID-UX-*` |
| 選んだこと | `meta/decisions/DEC-PLT-*` |
| 決まっていないこと | `meta/questions/Q-*` |
| 満たさないと成立しない条件 | `meta/requirements/platform.toml` の `TR-PLT-*` |
| 背景・意図・調査の説明 | `docs/design/` |

番号の取り方と meta の作法は `meta/README.md`。

### Phase 1 — リサーチ

上の3つを積む。事実は `EVID-UX-*`、読みどころは docs 側。3つとも済んでいる。

| | 事実 | 読みどころ |
|---|---|---|
| 競合の情報構造 | `EVID-UX-002` | [competitive-structure.md](competitive-structure.md) |
| 現行実装の棚卸し | `EVID-UX-001` | [inventory.md](inventory.md) |
| 制作の痕跡 | `EVID-UX-003` | [creator-traces.md](creator-traces.md) |

棚卸しから、要件との食い違いが4件出た。`Q-REC-003` `Q-RCL-004` `Q-PKG-002` `Q-PKG-003` として起票してある。Phase 3 のオブジェクト定義と同時に解く。

### Phase 2 — ジャーニーマップとユースケースの洗い直し

**差し替えではなく更新にした。** As-Is の観察は質が高く、捨てると価値が落ちる。足りなかったのは裏付けと、M2 で分かったことの反映だった。

- As-Is に痕跡の裏付けを入れた。`※出典あり` を付けた箇所は、誰かが実際に書いた言葉に対応している
- 工程の分断を数で書いた。8工程 / 4ソフト、渡るのはファイル名の一致だけ
- **To-Be に準備の段を書き足した。** As-Is の【調べる】は消えたが、代わりにデバイス選択・入力レベルの校正・回り込みの確認ができている。要件が求めるもので消せない
- テイクの世代と連続収録を To-Be に入れた
- `DEC-REC-008` を「品質の良し悪しを教えない」に紐付けた
- UC に `UC-F01-06`（録り直しても前のものを失わない）を足した。確度は動かしていない——新しい出典はどちらも Assumption なので、根拠にして格上げしない

残った宿題は Phase 3 へ。**収録項目が確認待ちという状態を持てないと `UC-F04-02` が成立しない。**

### Phase 3 — OOUI モデリング

オブジェクト抽出、関連、コレクションとシングルアウト、ビュー一覧、ナビゲーション、呼び出し。

対象オブジェクトの候補は、音源、方式、録音リスト、収録項目、テイク（世代あり）、原音設定、曲と曲バンク、入力デバイス、配布パッケージ。

成果物は `docs/design/ooui-model.md` と、画面構造の判断記録。

### Phase 4 — リブランディング

シンボルとワードマーク、アプリアイコン（macOS の squircle、Windows の `.ico`、Linux）、配色、書体、余白とリズム、図版の作法、モーション、マイクロコピーの声、README とリポジトリの見た目。

判断記録が要る論点が4つある。

- 配色を変えるなら実測をやり直す。 塗りに段 9 を使わない根拠は `crates/koeru-app/ui/src/styles/globals.css` に比の表として残っている。アクセントを cyan から動かすなら、同じ形で測り直して `DEC-PLT-022` の検査に通す
- UI 書体を変えるなら、同梱ライセンスを `deny.toml` の許可リストで確認し、3 OS の日本語表示を実機で見る
- ワードマークの書体は別問題。 アウトライン化すれば同梱ではなくなるが、派生物の可否は書体側のライセンスが決める。`deny.toml` の枠外なので個別に判断記録を残す
- ロゴをどう扱うか。 AGPL でソースが公開され、フォークが自由に作れる前提で、ロゴをコードと同じライセンスに載せるのか商標的に分けるのか。Made to be handed on との整合に関わる

### Phase 5 — デザインディレクション文書

Phase 3 と 4 の出力を、実装が参照できる形に畳む。原則、視覚言語、レイアウト、部品の粒度、コピーの規律、アクセシビリティの前提。

`react-conventions` skill との境界を決める。 skill はコードの規約、ディレクション文書は見た目の規約。同じ規則を2箇所に書かない。

### Phase 6 — 実装と差し替え

先に決めておくことが3つある。放置すると差し替えの直前に効く。

- 作り直しのあいだ main の `ui/` をどう扱うか。凍結するか、しないなら追従の頻度
- ブランチも CI を通し続ける。 DCO、`vp check`、`check-stories`、`check-ipc-calls`、axe、ライセンス検査。**`check-stories` は大文字始まりを輸出する `.tsx` すべてに story を要求する。部品をゼロから作り直すとは、部品と同じ数の story を書くということ。工数の実体はここにある**
- FSL と meta の更新を同じ PR に載せるか分けるか。画面構造の変更が `specs/` の状態機械に触るかは Phase 3 で判定する。触らないなら FSL は据え置き、触るなら FSL が先

## 先に潰すもの

main 側で、Phase 1 と並行して進める。ブランチでやると差し替えで一緒に消える。

- Rust 境界の見積もり。Phase 3 が終わった時点で、足りないコマンドの一覧を出す。改名は既に足りていない（[inventory.md](inventory.md)）
