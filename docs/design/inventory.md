# 現行実装の棚卸し

リデザインの出発点として、いま画面に何があるかを事実として並べる。`docs/design/redesign-plan.md` の Phase 1 のうち、聞き取り無しでも取れる事実の2つめ。

評価はしない。 食い違いだけを最後にまとめ、どう扱うかは判断記録に送る。

観察した事実そのものは `EVID-UX-001` が持つ。 ここは読みどころの説明で、数値と観察の出どころは Evidence 側にある。

## 画面

2つ。

| 経路 | 画面 | 構成 |
|---|---|---|
| `/` | 音源一覧 | 見出し、「新しく作る」の入力欄、「作りかけ」の一覧 |

収録画面のカードは上から「マイク」「いま録るところ」「録れたもの」「録れたもの一覧」「歌える曲」。「録れたもの」は直前のテイクがあるときだけ出る。「マイク」の中に「入力レベル」と「音の回り込み」が入れ子で入る。

## 目で見て分かったこと

Storybook の story を実寸で描いて確認した。

**収録画面は、いちばん重要なものが3番目にある。** 画面の上半分を「マイク」が占め、その下に「いま録るところ」が来る。KOERU の中核は録ることなので、視線が最初に当たるのは録音の準備になっている。準備は一度済めば二度と要らないが、置き場所は毎回同じ。

進捗がいちばん小さい。 `18 / 142 音（13%） · 1 / 3 曲が歌える` は見出しの下の等幅小文字で、画面上でもっとも目立たない要素のひとつ。`TR-RCL-19` が「常時両方出す」を求めた結果は満たしているが、大きさの指定は要件に無い。

カードが1種類しかない。 準備・録音・確認・一覧・報酬が、同じ枠線・同じ角丸・同じ背景に載る。段が違うことを示すのは見出しの文字だけ。

一覧が持っている情報は項目数だけ。 到達度も、歌える曲も、最後に触った時期も無い。名前と数字が1行に並ぶ。

ブランドが視覚に出ていない。 ロゴもワードマークも無く、Radix の slate と cyan と OS の既定書体だけ。`docs/product-vision.md` の Tone は画面上に形を持たない。

## 要件との食い違い

4件とも論点として起票済み。 Phase 3 のオブジェクト定義と同時に解く。ここでは直さない。

### 1. 収録画面に録音リストの項目 ID が出ている（`Q-REC-003`）

`TakeList` が行の識別子（`s001` など）を等幅で表示し、テイク・聴く・録り直しの3つの `aria-label` すべてに読み上げ用として入れている。

`TR-REC-18` の「発声を待っている面には項目 ID・ファイル名・エイリアス・oto などの内部表現を出さない」に当たるかどうかは、「発声を待っている面」を収録画面全体と読むか「いま録るところ」のカードだけと読むかで変わる。読み上げに入っている分、支援技術の利用者には確実に届く。

### 2. 一覧に到達度が無い（`Q-RCL-004`）

`LibraryScreen` は項目数だけを出す。カバレッジも歌える曲数も無い。

`TR-RCL-19` の「どちらかを隠さない」が一覧にも掛かるなら、いまの一覧は両方とも隠している。収録画面にしか掛からないなら食い違いではない。ただし `docs/product-vision.md` は進捗の見せ方を製品全体の方針として書いている。

### 3. 完成の状態は画面まで届いているのに、読まれていない（`Q-PKG-002`）

`ProgressView` は `coverage`（完成状態）と `handoff`（手渡し状態）を持ち、Rust から画面まで渡っている。**この2つを読んでいるのは story の固定値だけで、どの部品も描いていない。** 一覧の見出しは「作りかけ」だけで、完成を表す置き場所が無い。

`TR-PKG-34` が完成の条件を定め、`TR-PKG-36` の「完成条件を満たしていれば一覧上で完成として表示し」が一覧での表示を求めている。非公開のまま完成できることは `docs/product-vision.md` の中核のひとつで、その出口が画面に存在しない。値が来ていないのではなく、受け取って捨てている。

### 4. 改名の口が無い（`Q-PKG-003`）

一覧が「あとから変えられます。絵文字や記号も使えます。」と書いているが、生成された commands に改名が無い。画面の文言が、実装されていない機能を約束している。
