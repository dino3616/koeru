05+ / RESEARCH

配る — 調べたことと体験の見直し

P4g でもまだ微妙、というレビューから。「何度も、いくつもの形で配る」道具の書き出しを調べ、戦略から体験を見直す。
調べたこと — 配る道具と、「何度も、いくつもの形で配る」道具の書き出し
GAKUYA · GakuyaWebUTAU 音源をパッケージ化する web アプリ。既存の ZIP を読み、ファイルごとのタブで整えて ZIP を1つ生成する（下に詳しく）
Unity · Build Profiles「何を入れて、どう作るか」を名前付きの設定として持つ。1つのプラットフォームに複数（リリース用 · 開発用）。シーンを profile ごとに割り当てる。共有する設定と、profile だけの設定を分ける
Godot · Export presets書き出し先ごとの preset が、入れるリソース（含める · 除く）、名前 · アイコン · バージョンを持つ。一度作れば同じ preset で書き出し直す
Lightroom Classic · Export presetsよく使う書き出しを preset に保存し、「Export With Previous」で前回と同じ設定をもう一度。毎回ダイアログを埋めさせない
itch.io · butler の channelchannel ＝ 配布ページの1つのファイル枠。同じ channel に push するたびに新しい build が積まれ、版は channel ごとに数える。1つの channel は1つのダウンロード
Xcode · Archives organizer左に対象、中央にその対象の archive の一覧、右に選んだ archive の詳細と「検証」「配布」。作ったものは消えずに並び、あとから配り直せる
GitHub · Releasesrelease ＝ 版（タグ）＋ 説明 ＋ 添付ファイル。配ったものを版として残し、あとから見比べられる
Apple HIG · Progress indicators進みが分かるなら determinate で。いつも同じ場所に出す。操作のすぐ横に小さく出してよい
GAKUYA（きみがためtools）— 同じ責務の道具を読む
ファイルの確認ファイル一覧キャラクター説明書・利用規約インストール設定prefix.mapoto.ini周波数表編集
GAKUYA がやっていること
入り口既存の音源 ZIP を読み込む。音源ルート（character.txt のあるフォルダ）を探す
並べ方ファイルごとのタブ8つ。各タブに「〇〇を作成・更新する」のチェック
ファイルの確認キャッシュ（$read · *.uspec · setParam · vLabeler · __MACOSX）を消す · frq を作る · 他エンジンの周波数表を消す · WAV をモノラル / 44.1 kHz / 16 bit に · DC オフセット除去 · 文字コード
キャラクター音源名 · アイコン（bmp/jpg/gif/png を UTAU のアイコンに変換）· サンプル音声 · 管理者 · web · バージョン。character.yaml の立ち絵 · 透明度 · 高さ · 音声提供者 · phonemizer
説明書・利用規約readme.txt を自由文で書く（雛形なし）
インストール設定 · prefix.mapinstall.txt（UTAU へドロップで入る）。音階ごとの prefix / suffix と Voice Color
出口「zipファイルを生成する」→「ダウンロード」の1本。設定は残らない（ブラウザの中だけ）
KOERU では
KOERU が自動でやるファイルの確認タブのほぼ全部（TR-PKG-05 · 06 · 10 · 12 · 20 · 26）、install.txt（TR-PKG-09）、prefix.map と Voice Color（サブバンクから · TR-PKG-04）、文字コード。画面に出さない
取り入れる画像を選べばアイコン（100×100 BMP）に変換する（TR-PKG-07）。サンプル音声（character.txt の sample）。立ち絵の透明度と高さ
取り入れないファイル名で並べたタブ。受け取る人の問い（入れられるか · 何者か · どこまで使えるか）ではなく、作る側のファイルの都合で並んでいる。「作成・更新する」のチェックも同じ
足りないもの設定が残らないので、配り直すたびに全部のタブを確かめ直す。同じ音源から形の違う配布物を並べて出せない → KOERU は配布物の棚で埋める
GitHub の GakuyaWeb の画面の文言（src/i18n/ja.ts）と、エディタの構成（EditorView.tsx）から読んだ
パターン — ほかの道具でうまくいっていることを、KOERU に置き換える
パターンほかの道具KOERU では
1 名前付きの「配布物」入れる中身と作り方を、名前を付けてとっておく（Build Profile · preset · channel）。毎回フォームを埋めない「すべて」「単独音 A3」…を配布物として持つ。ユースケースの4つはそのまま4つの配布物
2 1つの配布物 ＝ 1つのファイルchannel は1つのダウンロード。push するたびに同じ枠の新しい版になるZIP はいつも1つ。版は配布物ごとに数える
3 共有するものと、配布物だけのものUnity は全プラットフォーム共通の設定と profile だけの設定を分ける画像 · 名義 · 声の提供者 · web · サンプル音声は音源で1つ。入れる枠 · 担当音域 · 名前 · フォルダ名は配布物ごと。利用規約は共通を配布物で上書きできる
4 作ったものは版として並ぶArchives · Releases · builds。消えずに並び、あとから見返し、配り直せる中身と ZIP の横に、その配布物の版の一覧。行ごとに Finder で表示
5 もう一度は1手Export With Previous。同じ設定で書き出し直すのに設定を開かない右上の白いボタン（⌘E）を押すだけ。配布物がいくつもあれば ⌥⌘E でまとめて
6 進みはその場でdeterminate な進みを、押したボタンのすぐ横に押したボタン（棚があればそのカード）が進みのバーになる。終わったら通知
書き出す設定ファイル — 多音階と声色は character.yaml と multi-prefix の両方で
ファイル読むもの中身
character.yaml の subbanksOpenUtau声色ごとに color · suffix、音階ごとに tone_ranges（S06b の担当音域）。Voice Color として表情を切り替えられる
prefix.map（音源ルート）UTAU 本体 · OpenUtausuffix の無い声色（Normal）の音階の割り当て。UTAU 本体が自分で読むのはこれだけ
prefix/〈声色〉.map（multi-prefix）presamp · おま☆かせ2020 · 最強プラグイン声色ごとの音階の割り当て。中身は音階の部分だけ（「_C5」。「C_C5」とは書かない）。声色の名前はファイル名
presamp.ini の [APPEND]presampClear · Whisper のように、ふつうの表情名でない声色を書いておく。KOERU は presamp.ini を同梱している（DEC-SYN-010）
単音階の配布物ではどれも書かない。選んだ枠から自動で作り、画面にはファイル名を出さない。今の TR-PKG-04（prefix.map と subbanks）に multi-prefix を足す
戦略 — 何を約束し直すか
前の見立て配布のページ ＝ 1回の書き出しを組み立てるフォーム。開くたびに「何を · どう」を決め直す
見直し配布のページ ＝ この音源から作る配布物の棚。配布物は一度作れば残り、録り足すたびに同じ配布物を書き出し直す
なぜUTAU の音源は、録り足し · 原音設定の直し · 規約の更新のたびに配り直される。しかも「全部入り」と「単独音だけ」のように、同じ音源から形の違う配布物を並べて出す。毎回組み立てるフォームだと、前と同じ中身で出すだけのために全部を確かめ直すことになる
約束「いつもの配布物を、いつでも1手で新しくできる」。新しい形で配りたくなったら、棚に1つ足す
体験 — 一度作って、何度も書き出す
1はじめて開く配布物「すべて」が1つだけある（全部の枠）。名義と規約が空でも書き出せる。押せば ZIP が1つ
2録り足したあと頭に「1.0.0 のあとに録った行 12」。押せば 1.0.1
3形の違う配布物を足す「＋ 別の形でも配る」で今の配布物を写すと、頭の下に棚が出る。枠を押して形を変える。たとえば「単独音 A3」
4いつもの配り直し⌘E。いくつもあれば選んで ⌘E、まとめて ⌥⌘E。中身は前と同じで、版だけが上がる
5配ったものを見返す中身の下に版の一覧。行ごとに Finder で表示
骨格 — 使う人で考え直す（ビギナー · 中堅は1つ、ベテランは n）
ビギナー · 中堅配布物は1つ。録り足すたび · 規約を直すたびに、同じ1つを配り直す。「配布物」という考え方を知らなくても配れてほしい
ベテラン同じ音源から「すべて」「単独音 A3」…のように形の違う配布物を並べ、録り足すたびにまとめて配り直す
約束1つのときは「配布物」という言葉も棚も出さない。2つにしても画面は組み替わらず、頭の下に棚が1段増えるだけ。下の中身 · ZIP · 版は同じ部品 · 同じ並び
前の D をやめた理由1つしか持たない人にも、列の頭と「＋」の列と 184 px のレーンを見せる。横に並べて見比べる力はベテランにしか効かない
