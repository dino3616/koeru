04+ / SKELETON

骨格 — 手渡す（S10 · S11 を考え直す）

S10 と S11 がほかの画面と違って見える理由を、戦略と要件までさかのぼって言葉にし、骨格を組み直す。表層はまだ決めない。
何が違って見えるのか — 他の画面と並べて
画面の型ほかの画面は「主語の名前 → 事実の数 → 右上に次の一手 → 縦に並ぶ節」の1枚。S10 は左がフォーム・右がインスペクタの2枚組で、S11 はサイドバーも無い全面の完了画面
選び方が分かれている「統合音源 / 多音階 / 単音階」のラジオと、サブバンクのチェックが別々にある。選んだ枠で構成は決まるのに、2か所で同じことを決めさせている。チェックの横の進み（%）は S06 の持ち物
言葉「name（音源名）」「version」のようなファイルのキー名、ファイルの木、exports/000001-v1.0.0.zip のようなパス。ほかの画面は UTAU の語彙で話し、パスは出さない
図形S11 の点の円と斜線の四角は、v3 で検討してほかの画面から外した図形。「完成」の札と「公開しなくても、これで完成です。」の説明文が残っている
祝い方書き出したことを「完成」として祝っている。ほかの画面は事実だけを置いて、褒めも叱りもしない
戦略・要件とのずれ
根拠決めてあること今の S10 / S11
P1 体験原則完成は公開と無関係。公開の有無を進み具合にも祝福にも使わないS11 が書き出した直後に「完成」を出す
TR-PKG-33 / 34完成と手渡しは直交。完成の判定は書き出し履歴を見ないS11 が2つを1画面で結ぶ
TR-PKG-30 · DEC-PKG-011利用規約は本人が書いた本文をそのまま。設問からの生成も雛形も持たないS10 の規約チップと雛形の文
TR-PKG-22 · 23選べる方式は、選んだ枠の素材が被覆できるものだけ方式を選ぶ所が無く、方式ごとに ZIP が分かれる（nagi/ · nagi_cv/）
TR-PKG-35進捗の分母に書き出し・作者・規約を入れない「書き出せるまで 3 / 4」のチェックリスト
TR-PKG-38通常の画面にパスを出さないファイルの木と exports/… のパス
戦略 — 手渡すで約束すること
問い：「受け取った人が、迷わず入れて、何者か分かり、どこまで使ってよいかが分かるか？」
主語：受け取る人から見た音源 ＝ 書き出した版。S06 の主語（今の音源）とは別のもの
ジョブ：P1 の「他人に使ってほしい」。完成とは別の、やってもやらなくてもよい一手。完成は S06 が持つ
守ること：完成を祝わない · 書き出しを進みに数えない · 本人が書いた文章だけを入れる · KOERU 固有のものを混ぜない（TR-PKG-31）· パスを出さない
受け取る人の3つの問い
入れられるかいつも両対応で書き出す。UTAU にはドロップ（UAR）、OpenUtau には ZIP。どちらで受けても同じ中身（TR-PKG-09 · 12）
何者か分かるか受け取った人の画面に出る名前・アイコン・立ち絵・名義・web。名前と画像は S06 と同じものを、ここでも直せる
どこまで使ってよいか本人が書いた利用規約。書かなければ規約の節は出ない（TR-PKG-30）
要件 — 置くものと、その持ち主
もの持ち主S10 での扱い
名前 · アイコン · 立ち絵S06 · S10S06 と同じものを、ここでも直せる。片方で直せばもう片方も変わる（写しを持たない）
入れる枠S10ここで選ぶ。声色 × 音階の並びは S06 と同じ。構成の名前（単音階 · 多音階 · 声色多音階）は選んだ枠から決まり、選ばせない
方式S10既定は「録った方式のまま」。方式の違う枠も1つの ZIP に入れられる（OpenUtau の JA Presamp が CV · VCV · CVVC を混ぜて引く）。選んだ枠すべてが被覆できるなら、下の方式へ降ろすこともできる（TR-PKG-22 · 23）
担当音域S06b選んだ枠の tone_ranges をそのまま書く。外した枠の高さを受け持つ枠が無ければ、その事実を出す
制作者名義 · 声の提供者 · webS10ここで書く。空でも書き出せる（TR-PKG-36）
バージョンS10前の版から次を出しておく（1.0.0 → 1.0.1）。書き換えられる
利用規約S10本人が書く本文だけ。雛形もチップも持たない
形式—いつも両対応（TR-PKG-12 の既定）。選ぶ操作を置かない。ZIP はいつも1つ
書き出せない理由S04 · S08事実を1行ずつ。「原音設定の確認が 12件」→ 原音設定へ。チェックリストにしない
書き出した版S10版 · 日時 · 構成 · 方式 · 大きさの一覧。行ごとに Finder で表示
書き出した直後S10 の状態新しい版が一覧の先頭に加わる ＋ OS の通知。S11 という画面は作らない
構造 — S10 は1枚で、S11 は S10 の状態になる
書き出せない主ボタンは押せない。理由の事実を主ボタンのすぐ下に1行ずつ
書き出せる主ボタン「書き出す ⌘E」。ZIP は1つ。大きさを先に出す（TR-PKG-24）
書き出し中画面はそのまま。主ボタンの場所に進みのバーだけ出す。読み戻し検証まで含む（REQ-PKG-106）
書き出したOS の通知で知らせる。版の一覧の先頭に新しい行が加わる
失敗したZIP を残さない。何が通らなかったかを1行で
どう組むか
A　フォーム＋インスペクタ＋完了画面（今）不採用
入力欄が主役で、ほかの画面と型が違う。S06 の持ち物を持ち直し、完了画面が書き出しを祝う。
B　音源のページから「書き出す…」のシート不採用
macOS らしい書き出しだが、名義と規約の長い文章がシートに収まらない。書き出した版の置き場が無く、シートを閉じると何を渡したか見えなくなる。
C　配布のページ1枚（主語は版）採用
ほかの画面と同じ型。上に名前と事実の数と主ボタン、下に「名前と画像 · 名義と版」「書き出すもの」「利用規約」「書き出した版」。書き出した直後もこのページのまま。
